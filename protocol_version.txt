Protocol v2, 2026-09-04

Change from v1: switched from issue-first to PR-first candidate enumeration.
Reason: issue-to-PR linking in the target repository is inconsistent (v1
yielded 0-4 candidates from 76 bug-labeled issues due to unlinked or
squashed fix PRs). PR-first selection uses merged PRs whose titles match
bug-fix language and whose diffs are 3-300 LOC across at most 4 files,
with the same rendering/layout/key-binding exclusion filter.
Candidate pool size at protocol v2: 64 candidates from 774 closed PRs.

Frozen commit: see frozen_commit.txt
Cutoff date: 2027-01-01 (all history)
Bug-title patterns: fix, bug, resolve, correct, repair, patch, issue,
regression, broken, crash, error, fail
Excluded paths: prompt_toolkit/renderer.py, prompt_toolkit/layout/,
prompt_toolkit/key_binding/, plus docs/tests/examples/config
Size filters: 3 <= LOC <= 300, files <= 4

Holdout-split seed: 137 (in draw_tasks.py)

Protocol v3, 2026-09-04
Change from v2: harness now resets to per-task pre-fix commit (parent of
reference PR merge commit) and restores reference-PR test files as the
correctness oracle, instead of running against a single frozen HEAD.
Reason: v2 harness ran agents against a repo state that already contained
every fix in the task list; tests trivially passed and provided no signal.
The frozen_commit.txt file remains as a metadata pin for the candidate
enumeration (task selection freeze), not as the per-run repo state.

Test-file identification heuristic: files under tests/, or with basename
starting test_, or ending _test.py.

Oracle: pytest on the identified test files. If a task has no test files
in its reference PR, the operator is warned and the outcome falls back to
the full-suite pass check (recorded but marked as no-oracle in the run
summary).
